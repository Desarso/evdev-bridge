# evdev-bridge

Forwards Sunshine's virtual keyboard and mouse into a Wayland compositor that has no
libinput backend, by re-injecting the evdev events through Wayland's virtual-input protocols.

## Why

When Hyprland runs inside an LXC container for game/desktop streaming, it has no libinput
backend, so the `/dev/input/event*` devices that Sunshine creates for remote input are
invisible to it: the stream shows the desktop, but keyboard and mouse do nothing.
evdev-bridge sits between the two: it reads Sunshine's devices directly and replays every
event as a Wayland client using:

- `zwlr_virtual_pointer_manager_v1` (wlroots virtual pointer) for mouse
- `zwp_virtual_keyboard_manager_v1` (virtual keyboard) for keyboard

```
Moonlight client ──► Sunshine ──► /dev/input/eventN ──► evdev-bridge ──► Wayland compositor
                                  "Keyboard passthrough"   (this)        virtual pointer +
                                  "Mouse passthrough"                    virtual keyboard
                                  "Mouse passthrough (absolute)"
```

## Features

- Finds Sunshine's devices by name (`Keyboard passthrough`, `Mouse passthrough`,
  `Mouse passthrough (absolute)`) and waits, polling every 2 s, until they appear.
- Relative and absolute pointer motion (absolute range 0-65535 mapped to the output),
  buttons (left/right/middle/side/extra/forward/back), and wheel scrolling.
- High-resolution scrolling: `REL_WHEEL_HI_RES` / `REL_HWHEEL_HI_RES` are accumulated in
  1/120-notch units and flushed on `SYN_REPORT` as smooth axis events plus discrete steps.
- Keyboard: uploads a `us`/`pc105` XKB keymap (shared via an unlinked temp file fd), tracks
  modifier state (Shift/Ctrl/Alt/Super/Caps/Num) and sends `modifiers` events, skips kernel
  autorepeat (the compositor repeats), and drops duplicate key presses within 100 ms.
- Binds the virtual pointer manager at v2 and attaches the pointer to the first `wl_output`
  when the compositor supports it.
- Single `poll()` loop over the Wayland fd and the evdev fds; exits cleanly on device
  hang-up or read errors so a supervisor (e.g. systemd) can restart it.

## Build

Dependencies: `gcc`, `make`, `libwayland-client`, `libxkbcommon` (development headers).

```bash
make                 # builds ./evdev-bridge-native
sudo make install    # installs to /usr/local/bin/evdev-bridge-native
```

The `protocols/` directory contains the client headers and glue code pre-generated by
`wayland-scanner`, so the build does not need `wayland-protocols` or `wayland-scanner`.

## Run

Run it inside the same session as the compositor, as a user that can read `/dev/input/event*`:

```bash
WAYLAND_DISPLAY=wayland-1 ./evdev-bridge-native
```

It logs to stderr. The compositor must expose `zwlr_virtual_pointer_manager_v1` and
`zwp_virtual_keyboard_manager_v1` (Hyprland and other wlroots-based compositors do).

## Limitations

- Keyboard layout is hardcoded to `us` / `pc105`.
- Every key event is logged to stderr (`SEND KEY: code=...`) for debugging. That is useful when
  diagnosing dropped keys but means typed input ends up in logs; remove the `fprintf` in
  `handle_keyboard_event` if that matters for your setup.
- No configuration flags; device names match Sunshine's defaults.
